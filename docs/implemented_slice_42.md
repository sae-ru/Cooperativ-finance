# Реализованный Slice 42: безопасные офлайн-черновики браузера

Статус: критерий приемки 128 закрыт исполняемым frontend-контрактом, тестами и
проверкой рабочего Docker-узла.

## Граница хозяйственного состояния

Когда браузер не видит локальный узел, он может сохранить предложение товара
или услуги только как запись `cooperative-browser-draft-v1` в IndexedDB.
Локальная запись имеет собственный `draft_id`, но не получает `event_id`,
`object_id`, подпись, номер последовательности или hash события.

Черновик явно содержит:

- `authoritative: false`;
- `review_required: true`;
- владельца `owner_user_id` и кооператив;
- заполненную форму и необязательную фотографию;
- время создания, изменения и удаления через семь дней.

Сохранение не вызывает upload и command API. Поэтому оно не может изменить
остаток, паевой счет, право, обязательство или репутацию.

## Повторная проверка

После восстановления связи ничего не отправляется автоматически. Участник
открывает локальный черновик кнопкой «Проверить», видит все поля и отдельно
нажимает «Опубликовать предложение». Локальная копия удаляется только после
успешного ответа узла. До этого интерфейс прямо сообщает, что ничего не
опубликовано и не зачислено на паевой счет.

Черновики показываются только тому `user_id`, который их создал. Выход и вход
другого пользователя в том же браузере не открывает чужой список.

## Недоверенное хранилище

IndexedDB не является источником доверия. При каждом чтении frontend проверяет
формат, владельца, срок, признаки `authoritative/review_required` и рекурсивно
запрещает серверные поля. Поврежденная или измененная вручную запись не
загружается в форму и удаляется из локального списка.

API и health-запросы PWA используют `NetworkOnly`; service worker не превращает
POST в фоновую очередь. Обновленная граница ошибок распознает устаревший CSS
lazy-chunk и один раз обновляет service worker/страницу вместо показа обычной
ошибки приложения.

## Проверка

- TypeScript typecheck прошел без ошибок;
- полный frontend gate: `70` test files, `202` tests;
- tests проверяют запрет вложенного `event_id`, tampered local record,
  offline save без upload/API, отсутствие auto-publish после reconnect и
  удаление черновика после явного успешного server commit;
- production PWA build: `1950` modules, `78` precache entries;
- Docker frontend пересобран и поднят через gateway `:8080`;
- в реальном браузере черновик сохранен, пережил полную перезагрузку, появился
  в «Черновиках на этом устройстве» и открылся только кнопкой «Проверить»;
- до сохранения, после сохранения и после повторного открытия в PostgreSQL было
  `434` signed events: локальный draft не создал серверного события;
- тестовый браузерный черновик удален после проверки, `/health/ready` остался
  `READY`.

Ручная публикация в рабочую демобазу не выполнялась, чтобы не создавать лишнее
предложение. Граница explicit review/publish/delete-after-success проверена
component test с отдельными утверждениями по каждому API-вызову.
