# Дизайн-система

Статус: production UI baseline.

## Характер

Интерфейс тихий, утилитарный и рассчитан на повторяющуюся работу. Он не должен
напоминать банковскую рекламу, криптобиржу, игру или социальную сеть.

## Геометрия

- базовый шаг: 4 px;
- основные интервалы: 8, 12, 16, 24, 32 px;
- border radius: 4 px для controls, максимум 8 px для cards/modals;
- icon button: стабильный квадрат 36 или 40 px;
- высота обычного input: 40 px, плотного table control: 32 px;
- desktop content max-width применяется только к формам и тексту, таблицы могут
  занимать рабочую ширину;
- страница не оформляется как карточка внутри фона.

## Цвет

Основной фон нейтральный светлый; поддерживается высококонтрастная тёмная тема
после MVP. Семантические семейства:

| Значение | Семейство |
|---|---|
| информация, ссылка | синий |
| подтверждено, доступно | зелёный |
| ожидание, срок, offline draft | янтарный |
| ошибка, отзыв, опасность | красный |
| спор, карантин | фиолетовый |
| нейтрально, архив | серый |

Цвет не является единственным носителем статуса. Градиенты, декоративные blobs
и доминирующая одноцветная палитра не используются.

## Типографика

- локальный system font stack без CDN;
- размер body не меньше 16 px на мобильном и 14 px в плотной desktop table;
- letter-spacing: 0;
- hero typography отсутствует;
- числа в колонках используют tabular numerals;
- единица измерения всегда видна рядом со значением;
- длинные identifiers сокращаются визуально, но копируются полностью.

## Компоненты

- Button: icon или icon+verb для команды;
- Status: icon + text + optional timestamp;
- DataTable: sticky header, column chooser, filters, export permission;
- Stepper: критические многошаговые операции;
- Timeline: хозяйственные события и передачи ответственности;
- EvidenceList: hash, type, author, time, access state;
- ExposureBreakdown: контуры пая и максимум убытка;
- ResponsibilityChain: люди, роли, scope и текущая сохранность;
- ApprovalPanel: summary hash, initiator, attesters, expiry;
- ConflictDiff: две версии и запрещённый auto-merge;
- CommandBar: допустимые действия объекта;
- Drawer: детали без потери списка;
- Modal: только короткое подтверждение, не длинная рабочая форма.

Знакомые действия используют lucide icons. Неочевидная иконка имеет tooltip и
accessible name.

## Таблицы

Для операционных данных таблица предпочтительнее набора карточек. Обязательны:

- устойчивые ширины колонок;
- перенос или ellipsis без перекрытия;
- сортировка только по поддерживаемым сервером полям;
- выделение строки не изменяет её высоту;
- keyboard navigation;
- сохранённые role-specific views;
- явное пустое состояние без маркетингового текста.

## Формы

- label не заменяется placeholder;
- серверная ошибка привязана к полю или summary;
- опасное действие показывает последствия до кнопки;
- destructive/financial command требует повторного подтверждения или step-up;
- кнопка не меняет ширину при loading;
- unsaved draft восстанавливается и явно маркируется;
- единица, scale и правила округления видны до ввода количества.

## Тексты

Используются хозяйственные глаголы: «Принять партию», «Передать сохранность»,
«Подтвердить исполнение», «Заблокировать гарантийный пай». Запрещены расплывчатые
«Продолжить» в критической финализации, «Успех» без объекта и манипулятивные
формулировки.

## Адаптивность

Проверяемые viewport минимум:

- 360x640;
- 390x844;
- 768x1024;
- 1366x768;
- 1440x900;
- 1920x1080.

На мобильном таблицы становятся списками только с сохранением ключевых полей и
доступа к полному объекту. Текст, badge, счетчик и кнопка не меняют размер
контейнера неожиданно.

## Accessibility

- WCAG 2.2 AA как целевой минимум;
- полная работа клавиатурой для критических сценариев;
- visible focus;
- screen reader labels;
- live region для результата фоновой операции;
- ошибки не обозначаются одним цветом;
- печатные формы читаются в grayscale.
